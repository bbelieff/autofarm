# 오토농장 (AutoFarm) — 제품·운영 설계서 v1

> 작성 2026-09-29 · v1.2(검토 반영 + 사용자 결정 8건 반영) · 상태: 설계 확정 전 초안 · 대상: 개발자·운영자·유지보수 인계자
> 농수산물 **위탁판매 한 바퀴**(소싱 → 가격 → 소재 → 상세 → 등록 → 발주 → 정산·세무)를 한 화면에서 돌리는 SaaS.
> 이 문서는 공개 레포용입니다. 강의 원문·공급처 목록·발굴 프리셋 수치 같은 비공개 자료는 레포 밖 비공개 부록에만 둡니다(§9).

## 1. 한 바퀴 — 스텝 지도

```
S0 연결설정 ─▶ S1 수요발굴 ─▶ S2 시점·시장검증 ─▶ S3 공급처매칭 ─▶ S4 가격설계 ─▶ S5 소싱리포트
                                                                                       │
S10 정산·재무·세무 ◀─ S9 주문·발주·송장 ◀─ S8 채널등록 ◀─ S7 상세제작 ◀─ S6 소재(이미지) ◀┘
        │
        └─▶ 제철캘린더·실패기록 → 다음 사이클 S1 입력으로 되먹임
```

자동화 수준: **자동**(사람 개입 없음) · **반자동**(시스템이 준비, 사람이 확인·클릭) · **수동**(입력 폼 제공)

| 스텝 | 하는 일 | 자동화 | 외부 연결 | 단계 |
|---|---|---|---|---|
| S0 연결설정 | 공급처·데이터·채널·AI·시트·피그마 연결, 사업자 정보(과세유형) | 수동 | 전부 | P0 |
| S1 수요발굴 | 입력 없이/품목군/아이템명 → 후보 키워드 목록 | 자동 | 데이터랩·검색광고·아이템스카우트 | P1 |
| S2 시점·시장검증 | 3년 피크 반복·1년 일간 진입일·그래프 유형·채널별 합격선·쿠팡 경쟁 | 자동(+쿠팡 1페이지는 반자동) | 동일 + 어사이드 | P1 |
| S3 공급처매칭 | 공급처별 옵션·등급·공급가·단위당가·재고·사진, 1·2·3순위 | 자동 | 공급처 커넥터 | P1 |
| S4 가격설계 | 채널별 판매가·등록가·쿠폰·옵션 추가금·끝자리·미끼옵션 | 자동(+시트 검산) | 구글시트 | P1 |
| S5 소싱리포트 | 추천 아이템 + 근거 + 공급처 표 + Top3 사진 + 판매가 + 인계서, 제철캘린더 저장 | 자동 | — | P1 |
| S6 소재 | 공급처 이미지 수집·보정(글자 지우기·1000×1000·업스케일)·AI 생성·슬롯 배치 | 반자동 | 공급처·AI | P2 |
| S7 상세제작 | 상품명·카피(섹션+CS 방어문구)·당근 소식/광고/리드폼 문구 → 피그마 채우기 → 780px 분할 내보내기 | 반자동 | AI·피그마 | P2 |
| S8 채널등록 | 쿠팡 등록(API 또는 어사이드) · 당근 등록 패키지 → 어사이드 | 반자동 | WING API·어사이드 | P3 |
| S9 주문·발주 | 주문 수집 → 공급처 매핑 → 발주 엑셀 → **공급처 결제 페이지 연결** → 송장 수집 → 채널 송장 등록 | 반자동 | WING API·공급처·어사이드 | P3 |
| S10 정산·재무 | 채널 정산·매입·광고비·리뷰비·택배비 → 손익 → 부가세·종소세 자료 → 세무사 패키지 | 자동(+증빙 업로드) | WING API·엑셀 업로드 | P4 |
| S11 운영 경보 | 공급처 품절·가격 변동 감지 → 판매중지/쿠폰 조정 제안, 연결 끊김 알림 | 자동 | 커넥터 | P3~ |

## 2. 스텝별 기능 정의

### S0. 연결 설정 (Connections)

| 연결 종류 | 방식 | 저장하는 것 | 비고 |
|---|---|---|---|
| 어드민플러스 계열 공급처 | 공식 Open API | 공급처별 API 키 | 공급처당 분당 60회·일 1만 회 한도 → 워커가 속도 제한 |
| 발주오라 계열 공급처 | 로그인 세션(내부 JSON) | 아이디·비밀번호 또는 세션 쿠키 | 토큰 갱신 후 상품·옵션 조회 |

- **연결마다 상태**를 가진다: `미설정 · 정상 · 만료(재로그인 필요) · 차단(캡차·2단계 인증) · 오류`. 매일 1회 헬스체크.
- 대신 로그인 연결은 **동의 시각·목적·보관 만료일**을 함께 저장한다. 만료일이 지나거나 세션이 끊기면 세션 쿠키는 자동 파기하고 재로그인을 요청한다. 캡차·2단계 인증이 뜨면 해당 작업은 재시도하지 않고 멈춘다.
- 사업자 정보: 상호·사업자번호·**과세유형(일반/간이) 선택**(예: 운영자 일반, 친구 간이)·주 취급 품목 과세 구분(면세/과세) → S10에서 사용.

### S1. 수요 발굴 (Discovery)

**입력 3모드** — 아무것도 넣지 않아도 돌아간다.

| 모드 | 입력 | 동작 |
|---|---|---|
| A. 무입력 | 판매 목표 시점(기본: 오늘+3주부터 한 달) · 대분류(과일/농산/수산, 기본 전체) | 카테고리 발굴 → 후보 생성 |
| B. 품목군 | 「과일」「수산」「사과」 같은 넓은 말 | 연관 키워드 확장 → 후보 생성 |
| C. 아이템명 | 「감홍사과」「햇밤」 같은 구체 키워드 | 해당 키워드 + 연관 키워드만 검증 |

**발굴 파이프라인**(모드 A 기준, B·C는 중간부터 진입)

1. 데이터랩 쇼핑인사이트: 분야(식품 › 농산물 › 과일 등), **작년 같은 구간**의 인기 키워드 목록.
2. 아이템스카우트 아이템 발굴: 카테고리 3차까지, 과거 기간, 쇼핑성, 주요 브랜드 제외, 검색수 하한, 상품수 적은 순(필터 값은 **발굴 프리셋**, §6-3).
3. **수식어 필터**: 지역·품종·특성이 붙은 중소형 키워드만 남김(「사과」✕ 「감홍사과」○). 규칙 + AI 판별(인명·채널명·다른 형태 — 아이스·칼집 등 — 제외).
4. **역방향 발굴**: 연결된 공급처의 판매중 상품명에서 키워드를 뽑아 후보에 합침(“지금 떼올 수 있는 것”에서 출발).
5. **연관 키워드 확장**: 후보마다 연관 키워드를 펼쳐 같은 계열끼리 묶고, 3년 피크 검색수가 가장 큰 것을 **대장 키워드**로 지정.
6. 제외 규칙: 무른 품목(CS 위험) 표시, 브랜드 상품(지재권) 제외, 가공품(과세) 표시.

출력: `후보 키워드[]` — 각 후보에 대장 여부, 묶음, 출처(데이터랩/아이템스카우트/역방향)를 붙인다.

### S2. 시점·시장 검증 (Timing & Market)

| 검증 | 방법 | 파라미터(기본값, 조정 가능) |
|---|---|---|
| 시즌 반복 | 3년 월간 그래프에서 같은 달 봉우리가 해마다 나오는지 | 반복 연수 ≥ 2 |
| 피크 검색량 | **확정값만**(예측 구간 제외) | — |
| 이슈 스파이크 제거 | 1~2일 반짝 봉우리 감지 → 진짜 봉우리 기준으로 재계산 | 스파이크 폭 ≤ 3일 |
| 진입일 | 1년 일간 그래프, 최고점=100 → **진입 %**를 처음 넘는 날 | **진입 % = 25** |
| 등록 권장일 | 진입일 − 리드타임 (올해 날짜로 환산) | **리드타임 = 5일** |
| 그래프 유형 | 뾰족(한 달) · 완만(석 달 이상) · 두 봉우리 · 급락 | 유형별 진입 전략 표시 |
| 후반 진입 | 완만형만 하강 구간 X~Y% 지점 허용 | 30~40% |
| 채널별 합격선 | 채널마다 피크 검색량 하한 | 프리셋(§6-3) |
| 쿠팡 경쟁 | 쿠팡 상품수·쿠팡 경쟁강도·로켓 개수·1페이지 시세 | 로켓 허용 개수 |
| 시장 크기 비 | 피크 검색수 ÷ 쿠팡 상품수 | 하한 비율 |

- **두 출처로 교차 검증**해 신뢰를 만든다.
  - 아이템스카우트: 3년 월간·1년 일간 절대 검색수(주 출처).
  - 공식 API 재구성: 데이터랩 일간 **상대값**(0~100) × 검색광고 **최근 30일 절대값**으로 과거 절대 검색수를 환산. 아이템스카우트 세션이 끊겨도 소싱이 멈추지 않는다.
  - **주 판정은 아이템스카우트 절대값**, 재구성 값은 보조 지표다. 재구성은 조회 구간의 최대값이 100으로 정규화되므로, 피크가 최근 30일 밖이면 환산이 왜곡된다 — 환산식·기준 창·정규화 기준을 sourcing_run에 함께 저장한다.
  - 두 값의 차이가 임계값(기본 30%, 설정값)을 넘으면 경고. 아이템스카우트 값이 없어 재구성만으로 판정한 후보는 최고 판정을 **시도**로 제한한다.
- 쿠팡 1페이지 시세·로켓 개수는 아이템스카우트 쿠팡 지표로 먼저 채우고, 없으면 **어사이드 확인 요청**을 만들어 반자동으로 받는다. 확인 요청은 리포트 생성을 막지 않는다 — 값이 없으면 쿠팡 판정을 **시도**로 제한하고 「미확인」 배지를 붙인 뒤, 값이 들어오면 판정을 다시 계산한다.
- **판매 목표 구간과 등록 권장일 연결**: 실행 입력의 목표 구간(sourcing_run.target_window)을 기준으로, 등록 권장일이 이미 지났거나 구간 밖이면 사유 코드(`ENTRY_PASSED`·`ENTRY_TOO_EARLY`)와 함께 보류/제외 처리한다(두 봉우리·완만형 후반 진입은 예외 규칙 적용).

출력: `판정`(추천/시도/보류/제외) + 사유 코드 + 등록 권장일 + 그래프 유형.

### S3. 공급처 매칭 (Supplier Match)

1. 대장 키워드를 **짧게**(수식어 뗀 형태 포함) 모든 연결 공급처에 검색.
2. 옵션을 **정규화**: 중량(kg)·과수·크기 등급(꼬마/소/중/대/특)·품질 등급(특품/정품/가정용/못난이)·포장.
3. 계산: **배송비 포함 공급가**, **kg당 단가**, (과수가 있으면) 과당 단가.
4. 상태: 판매중/품절/비활성, 재고, 발주 마감 시각, 택배사, 제주·도서산간 추가비.
5. **1·2·3순위**: 같은 등급·중량 기준 배송비 포함 단가가 낮은 순.
   - 단위를 환산할 수 없는 옵션(중량 없음 등)은 순위에서 빼고 사유 코드를 붙여 따로 보여준다.
   - 원산지 표기가 상품명의 지역명과 다르면 **1순위에서 제외**(경고와 함께 2순위 이하로).
   - 제주·도서산간 추가비, 합포장 조건, 발주 마감 시각은 옵션 필드로 보관해 S4·S9에서 쓴다.
6. **공급처 제공 사진**: Top3 공급처 상품의 대표·상세 이미지 URL을 받아 썸네일로 저장(원본 출처 기록).

출력 표(리포트 그대로 사용):

| 순위 | 공급처 | 상품명 | 품질 등급 | 옵션(중량·과수) | 공급가 | 배송비 | 배송비 포함 | kg당 | 재고/상태 | 발주 마감 | 사진 |
|---|---|---|---|---|---|---|---|---|---|---|---|

### S4. 가격 설계 (Pricing)

- 채널별 공식(판매가 대비 순마진율 m, 채널 수수료 f):
  - 판매가 = 배송비 포함 공급가 ÷ (1 − m − f)
  - 당근 f = 0.033 · 쿠팡 f = 0.12(보수적) — 워크스페이스 설정으로 변경 가능
  - 쿠팡 등록가 = 실판매가 + 쿠폰액(기본 10,000) → 도매가가 오르면 옵션가를 건드리지 않고 쿠폰만 줄인다
- 옵션 추가금액 = 해당 옵션 판매가 − 최저 옵션 판매가(자동 계산, 입력 실수 방지)
- 끝자리 규칙: 최저 옵션은 내림(x,800/x,900 → 미끼), 나머지는 올림(x,900) 선택
- 검증 게이트: 끝자리·쿠폰 적용 후 **옵션 가격이 중량 순으로 단조 증가**하는지, 쿠폰액이 채널 허용 범위 안인지 확인. 위반하면 수정안을 제시
- price_plan에는 적용한 배송비 내역(기본·추가비)을 분리해 저장
- 마진율은 **품목마다 결정**: 소싱가 · 당근 시장가 · 쿠팡 시장가를 나란히 보여주고 사용자가 확정
- **시트 연동**: 사용자의 구글 시트(소싱조사·마진계산 탭)에 입력값을 쓰고, 시트가 계산한 판매가를 다시 읽어 **리포트에는 시트 값**을 표시. 앱 내장 계산과 1원이라도 다르면 경고(시트 수식 오염 감지)
- 시트 연동 안정화: 시트 템플릿 버전을 고정(열 매핑 버전 기록), 계산값 읽기는 재계산 지연을 고려해 재시도(3회·5초 간격), 반올림 규칙을 시트와 통일
- 시트가 없는 사용자는 앱 내장 계산만 사용(기본 폴백)

### S5. 소싱 리포트 (Report)

한 번의 실행 = 한 리포트. 공유 링크·PDF 내보내기.

1. **요약**: 채널별 추천 1~2개 + 대안 1개, 등록 권장일, 예상 판매가.
2. **고른 이유(로직 추적)**: 후보마다 S1→S2 각 관문 통과/탈락과 사유, 사용한 파라미터 값(진입 %·합격선 등).
3. **데이터 근거**: 아이템스카우트 수치(피크 검색수·상품수·경쟁강도 네이버/쿠팡·Top10/40 매출) + 데이터랩 그래프(3년 월간·1년 일간, 진입선 표시) + 공식 API 재구성 값 비교. 조회 시각과 출처를 모든 숫자에 붙인다.
4. **공급처 표**(S3) + **Top 1·2·3 공급처 사진**.
5. **판매가 표**: 옵션별 공급가 · 채널별 판매가 · 쿠팡 등록가/쿠폰 · 옵션 추가금 · 마진액·마진율(시트 값).
6. **탈락·보류 목록**과 사유(“공급 0곳 — 열리면 알림” 등 → S11 감시 대상으로 등록).
7. **인계서**: 다음 스텝(S6·S7)이 쓸 확정값 묶음 — 고정 스키마(`handoff`: 확정 품목·대장 키워드·확정 공급처와 옵션·판매가 표·등록 권장일·사진 후보). 사용자가 **채택**을 눌러야 생성된다.
8. **되먹임 규칙**: 채택한 품목 → 제철캘린더에 기록. 탈락·보류 후보 → 전부 자동으로 실패·보류 기록(다음 시즌 입력). 시점을 놓친 합격 품목 → 캘린더의 내년 칸.
- 공유 링크는 워크스페이스 한정 기본, 외부 공유는 만료가 있는 토큰으로만. PDF는 한글 폰트 내장. 리포트는 metric_snapshot ID를 참조해 값이 고정된다.

### S6. 소재 (Assets)

- 공급처 이미지 자동 수집 → 품질 점수(해상도·글자 포함 여부) → 슬롯 배치(대표·A컷·B컷·단면·포장·농장·농부).
- 보정: 글자·워터마크 지우기, 1000×1000 정사각, AI 업스케일, 밝기·색 보정.
- 생성: AI 이미지 생성·편집 — **기본 제한 없음**. 사용자에게 한 번 책임 고지 동의를 받고, 모든 이미지에 `출처(공급처/직접촬영/AI생성/참고)`와 원본 링크를 기록.
- 출력: 사진 슬롯표 + 보정본 파일.

### S7. 상세 제작 (Detail Page)

- 텍스트: 상품명(채널별 규칙) · 상세 카피(섹션 구조 + CS 방어 문구 + CS 연락처 필수 검사) · 당근 소식 본문 · 광고 문구 · 리드폼 문구 · 상품정보고시.
- **피그마**: 운영자가 만든 템플릿 파일을 사용자 피그마로 복제 → **오토농장 피그마 플러그인**이 서버에서 카피·이미지를 받아 레이어에 채움 → 사용자가 피그마에서 직접 수정 → 플러그인이 전체 이미지를 내보내 서버에 업로드 → **서버가 780px 분할**·대표이미지 생성.
  - 플러그인 인증은 워크스페이스별 **단기 업로드 토큰**, 템플릿은 파일 키·버전을 고정(템플릿 버전을 결과물에 기록).
- 당근용: 사진 7장 세트 + 메뉴판 등록값 + 소식·광고·리드폼 문구 = **당근 등록 패키지**.

### S8. 채널 등록 (Listing)

- 쿠팡: WING Open API로 상품 생성·옵션·쿠폰(가능 범위) → API가 막는 항목은 **어사이드 지시서**로.
- 당근: **어사이드 지시서 + 파일 묶음(zip)** 생성 → 사용자가 어사이드에서 실행 → 결과(상품 링크·스크린샷)를 업로드하면 등록 완료 처리.
  - aside_task: 지시서 버전·zip 해시·결과 검증 상태(미수신/수신/검증완료/불일치). 결과 검증 = 링크 형식·필수 스크린샷·가격·옵션 대조.
- 등록 전 **게이트 체크리스트**(CS 번호·고시·옵션 추가금·금지어·사진 출처) 통과해야 패키지 발행.

### S9. 주문·발주·송장 (Orders)

1. 주문 수집: 쿠팡 = API 주기 조회 · 당근 = 주문 엑셀 업로드(또는 어사이드 수집).
2. 상품 ↔ 공급처 옵션 매핑(1순위 품절 시 2순위 제안).
3. **발주서 엑셀 생성**: 공급처 양식별(어드민플러스 대량주문 양식 등), 공급처별로 묶음.
4. **결제는 사람이**: 공급처 **주문·결제(적립금/예치금/카드) 페이지로 바로 가는 링크**를 발주 건마다 제공. 결제 금액·적립금 잔액(조회 가능 시)을 옆에 표시.
   - purchase_order 결제 상태: `미결제 → 결제확인 → (부분)취소`. 결제확인은 공급처 주문 상태 조회(가능 시) 또는 사용자 확인 + 증빙(캡처·영수증)으로. **결제확인 전에는 송장 수집 대상이 아니고**, S10 매입에도 잡히지 않는다.
5. 송장 수집: 공급처 API/세션으로 운송장번호 조회 → 쿠팡 = API 송장 등록 · 당근 = 운송장 일괄 등록 엑셀 생성(또는 어사이드).
6. 예외: 품절·취소·주소 오류 → 할 일 목록으로.
7. **중복 방지**: order = (채널, 채널 주문번호) 유일, shipment = 운송장번호 유일. 같은 엑셀을 두 번 올리거나 API와 엑셀이 겹쳐도 한 건으로 처리.

### S10. 정산·재무·세무 (Finance)

- **과세 구분의 원천**: item.tax_class(면세/과세/혼합)와 귀속 기준. 가공이 들어간 품목은 과세로 표시(S1 가공품 표시와 연결).
- **취소·반품 상태**: order에 취소/반품/부분환불 상태를 두고, 손익·부가세는 실수령액 − 환불 기준으로만 집계.
- **원장**: 주문 한 건마다 매출(결제액·쿠폰 반영 실수령액) · 채널 수수료 · 매입(공급가+배송비) · 광고비 · 리뷰비용 · 기타 비용을 연결.
- 정산: 쿠팡 = 정산 API · 당근 = 정산 내역 엑셀 업로드. 정산 예정일로 **현금 흐름 달력**(돈이 먼저 나가는 구간 경고).
- 손익: 주간·월간 손익계산서, 품목·채널별 마진.
- **부가세 신고 자료**: 기간별 매출(채널별·면세/과세 구분·카드/현금영수증/기타), 매입(계산서·카드·현금영수증), 과세유형(간이/일반)별 서식 초안.
- **종합소득세 자료**: 연간 수입·필요경비 집계.
- **세무사 전달 패키지**: 위 자료 + 증빙 목록(업로드한 계산서·영수증 파일) + 요약 1장을 엑셀·zip으로.
- 고지: 세무 계산은 참고 자료이며 신고는 세무 전문가 확인 전제.

### S11. 운영 경보 (Monitoring)

- 공급처 **품절·비활성 전환** 감지 → 해당 상품 판매중지 제안(“전량 품절 뒤 주문 몰림” 방지).
- 공급가 변동 → 쿠팡 쿠폰액 조정 제안.
- 보류 품목의 공급 재개 알림.
- 연결 만료·차단 알림.

## 3. MVP 범위

**MVP = P0 + P1 (소싱 한 바퀴)**. 사용자 2명이 매주 월요일 소싱을 이 제품으로 끝낼 수 있으면 완료.

| 포함 | 제외(다음 단계) |
|---|---|
| 로그인(2명)·워크스페이스·연결 설정·암호화 저장 | 가입·결제·요금제 |
| 어드민플러스 API 커넥터, 발주오라·자체몰 세션 커넥터 1종씩, 수동/엑셀 가져오기 | 공급처 전수 커넥터 |
| 데이터랩·검색광고 API, 아이템스카우트 세션 수집 | 쿠팡 1페이지 직접 크롤링 |
| S1~S5 전부 + 제철캘린더 | S6~S11 |
| 구글 시트 소싱조사·마진계산 동기화 | 시트 외 스프레드시트 |
| 리포트 웹 화면 + PDF | 리포트 공유 권한 세분화 |
| AI: 수식어·이름 판별(운영자 키, 사용량 기록) | 사용자 키 교체 UI(P2) |

**P1 안의 순서**: ① 데이터랩·검색광고·아이템스카우트 + 그래프 분석 + 판정 → ② 어드민플러스 + 수동/엑셀 + 옵션 정규화 + 가격 엔진 → ③ 리포트 화면 → ④ 발주오라·자체몰 커넥터, 시트 쓰기, PDF. ①~③만으로도 매주 소싱에 쓸 수 있게 만든다.

**MVP 완료 기준(검증 방법)**

1. 입력 없이 실행 → 채널별 추천·대안이 나오고 모든 숫자에 출처·조회 시각이 붙는다.
2. 과거 수동 소싱 결과(운영자 보관 사례 2건)를 같은 조건으로 재현했을 때 추천 품목·등록 권장일이 일치하거나, 다르면 이유가 리포트에 나온다.
3. 공급처 표가 등급·옵션·배송비 포함가·kg당 단가·재고로 나오고 Top3 사진이 뜬다.
4. 판매가가 사용자 시트 값과 원 단위로 일치한다.
5. 아이템스카우트 세션이 끊긴 상태에서도 공식 API만으로 리포트가 나온다(판정 상한 「시도」 + 경고).
6. 월요일 소싱 한 번(실행 + 확인 + 채택)이 **2시간 안에** 끝난다.

## 5. 아키텍처

```
[브라우저: Next.js 웹]──┐                    ┌─ 공급처(API/세션)
[피그마 플러그인]───────┼─▶ API(Next.js) ─▶ Postgres(작업 큐 포함)
[어사이드: 지시서 실행]─┘         │              ▲
                                  └─▶ 워커(Node + Playwright) ─┼─ 네이버 API·아이템스카우트
                                                                ├─ 쿠팡 WING API
                                                                └─ AI 프로바이더
                         파일 저장: VPS 디스크(S3 호환 인터페이스로 추상화)
```

| 구성 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript 전 구간 | 웹·워커·플러그인 공용 타입 |
| 웹·API | Next.js(App Router) | 화면과 API를 한 앱에 |
| 워커 | Node + Playwright | 세션 로그인·페이지 읽기, 긴 작업 분리 |
| 작업 큐 | pg-boss(Postgres) | 별도 Redis 없이 VPS 한 대로 |
| DB·ORM | Postgres 16 + Drizzle | 마이그레이션 코드화 |
| 인증 | Auth.js(이메일 매직링크 또는 비밀번호) | 2명 규모에 충분 |
| 파일 | 로컬 디스크(S3 호환 어댑터) | 비용 최소, 나중에 오브젝트 스토리지로 교체. 파생 이미지 90일 보관·리포트 스냅샷 영구, 디스크 사용량 헬스체크 |
| 배포 | 도커 컴포즈(dev·prod 2벌) + 리버스 프록시 | VPS 한 대 |
| 테스트 | Vitest(도메인 로직) + 커넥터 계약 테스트(녹화 픽스처) + Playwright(E2E 소수) | 커넥터 고장이 유지보수의 핵심 비용 |

**워커 운영 규칙**(VPS 한 대에서 메모리 폭주 방지)

- 브라우저 작업 동시 실행 1, 브라우저 컨텍스트당 세션 1, 작업마다 타임아웃, N건마다 브라우저 재시작, 컨테이너 메모리 상한.
- 작업 멱등 키 = `sourcing_run_id + 단계`. 실패가 반복된 작업은 실패 보관함(DLQ)으로 옮기고 알림.
- 어사이드 확인 요청처럼 사람을 기다리는 작업은 별도 큐 — 자동 파이프라인을 막지 않는다.

**모노레포 구조**

```
apps/web            화면 + API
apps/worker         작업 실행기(수집·브라우저 자동화)
apps/figma-plugin   (P2) 템플릿 채우기·내보내기
packages/core       도메인 로직(진입일·그래프 유형·가격·옵션 정규화) — 순수 함수, 단위 테스트
packages/connectors 커넥터(공급처 플랫폼 유형별 · 데이터 · 채널) — 공통 인터페이스
packages/ai         프로바이더 추상화·사용량 기록
packages/db         스키마·마이그레이션
config/             프리셋 예시(*.example.json) — 실제 값은 비공개 파일
```

**커넥터 공통 인터페이스**(공급처)

```ts
interface SupplierConnector {
  kind: 'adminplus' | 'baljuora' | 'cafe24' | 'custom-session' | 'manual';
  healthCheck(ctx): Promise<ConnectionStatus>;
  searchProducts(ctx, keyword): Promise<SupplierProduct[]>;   // 옵션·이미지 포함, 정규화 전 원본 보존
  getOrderLink?(ctx, productId): string;                      // 결제 페이지 연결(S9)
  submitBulkOrder?(ctx, rows): Promise<OrderResult>;          // 가능한 플랫폼만(P3)
  getTracking?(ctx, orderIds): Promise<Tracking[]>;
}
```

공급처 **개별 인스턴스**(이름·URL·merchantId 등)는 코드가 아니라 **데이터**(DB 시드)로 둔다. 레포에는 플랫폼 유형별 어댑터만 있다.

## 7. 보안·비밀 관리

- 공급처 비밀번호·세션 쿠키·API 키는 **봉투 암호화**(항목별 데이터 키 AES-256-GCM, 마스터 키는 서버 환경변수) 후 DB 저장. 화면에는 끝 4자리만.
- 로그·에러 리포트·AI 프롬프트에 비밀값·구매자 개인정보를 넣지 않는다(로거 레벨에서 가림 처리).
- 워크스페이스 간 데이터 격리(모든 쿼리에 workspace_id 조건, 테스트로 강제).
- 대신 로그인은 사용자 본인 계정·본인 동의로만. 캡차·2단계 인증이 뜨면 **자동 우회하지 않고** 사용자에게 재로그인 요청.
- 수집 속도 제한(공급처별 한도 준수), 요청 간 간격, 동시 1세션.
- 공개 레포: 비밀값 커밋 금지(gitleaks CI), `.env*`·비공개 프리셋·공급처 시드는 `.gitignore`.
- 커넥터 녹화 픽스처는 **스크러버를 거쳐야 커밋 가능**(상품명·URL·merchantId 치환, 가격 범주화, 날짜 상대화) — CI에서 검사. 실제 값으로 하는 검증(골든 테스트)은 비공개 로컬 픽스처로만.
- 운영자 AI 키는 워크스페이스별 **월 예산 한도**(비용 상한)를 둔다. 이미지 생성 내용 제한은 두지 않되(§0), 모든 산출물에 출처·생성 여부를 기록.

## 8. 운영 체계

### 8-1. 개발 흐름

- 이슈 → 브랜치(`feat/S3-adminplus-connector`) → PR(체크리스트: 테스트·마이그레이션·문서) → CI(타입·린트·단위·계약 테스트·gitleaks) → main 병합 → dev 자동 배포 → 확인 후 prod 수동 배포.
- 마일스톤 = P0~P5, 라벨 = `step:S0~S11` · `type:feat/bug/chore/docs/research` · `prio:high/med/low` · `area:connector/core/web/worker/infra`.

### 8-2. 환경

| 환경 | 위치 | 데이터 |
|---|---|---|
| local | 개발 PC(도커 컴포즈) | 가짜 데이터 + 녹화 픽스처 |
| dev | VPS `autofarm-dev` 컴포즈 | 운영자 계정 실제 연결(읽기 위주) |
| prod | VPS `autofarm-prod` 컴포즈 | 사용자 2명 |

- 같은 VPS에 다른 서비스가 있으면 **디렉터리·포트·컨테이너 이름·메모리 상한을 분리**하고 기존 서비스 설정은 건드리지 않는다.
- **기존 VPS 실측(2026-09-29)**: 1 vCPU · RAM 3.9GB(사용 가능 약 2.5GB) · 스왑 4GB(약 1GB 사용 중) · 디스크 여유 26GB(47% 사용) · 도커 29.7·compose v5.5 설치 · 사용 중 포트 22·80·443·2019·3000·3100·8765(+Tailscale 8642·9119). 경영일지·모아워크·카페봇·헤르메스가 같이 돈다.
- 배정안: `/opt/autofarm/{dev,prod}` · 포트 dev 3310, prod 3320(127.0.0.1만) · 컨테이너 메모리 상한 합계 약 1.4GB(web 384MB·worker+Chromium 768MB·Postgres 256MB, dev는 필요할 때만 켬) · 브라우저 작업 동시 1.
- **테스트 주소 = Tailscale(도메인 구매·공용 Caddy 수정 없음)**: VPS는 이미 Tailscale에 붙어 있고 인증서 도메인 `srv1589249.tailc5e064.ts.net`이 발급 가능하다. `tailscale serve`로 prod를 `https://srv1589249.tailc5e064.ts.net`(dev는 다른 HTTPS 포트)에 연결 → 운영자·친구만 접속(친구는 Tailscale 앱 설치 + 노드 공유 초대). 인터넷 공개가 필요해지면 `tailscale funnel`(ts.net 주소 공개) → 정식 도메인 순서로 넘어간다. 공급처 로그인 정보를 다루므로 **테스트 기간에는 비공개(serve)가 기본**.
- 로컬 테스트는 `localhost`. 화면 시안·리포트 미리보기처럼 서버가 필요 없는 것은 정적 HTML로 만들어 비공개 링크로 공유할 수 있지만, 연결·수집·저장은 서버가 있어야 한다.
- 정식 도메인은 외부 사용자(P5) 때 결정. 부하가 늘면 새 VPS로 옮긴다(컴포즈 그대로 이전).
- 백업: prod DB 매일 덤프(7일 보관) + 파일 저장소 주 1회 → **암호화해 VPS 밖 1곳으로 복사**. 마스터 키는 VPS 밖에 별도 보관. 분기 1회 복원 훈련.
